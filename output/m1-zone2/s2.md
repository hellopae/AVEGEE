## ภาพอ้างอิงและการเตรียม

วัดก่อนวาดด้วย PIL: บ้านโซน 1 ทั้ง 4 ไฟล์ รวม alpha bbox และ SHA-256 ใน `s2/reference-measurements.json` ภาพวัสดุและภาพบริบทวัดใน `s2/context-reference-measurements.json`

แนบให้ตัววาดครั้งละ 3 ภาพตามลำดับ: [1] บ้านโซน 1 ของแบบนั้น [2] `img/map-v5/st-sala-asia.webp` [3] `img/map-v5/st-tarang-asia.webp` ไม่แนบ guide ที่มีกรอบ/ตัวอักษร ใช้ guide เป็นบริบทตรวจเท่านั้น

ส่ง prompt EN ตามสเปกแทนเฉพาะ `{DESC}` และต่อ Negative พื้นฐาน + Negative บ้านตามต้นฉบับทั้งชุด ค่า `transparent_background=false` เพราะสเปกสั่งวาดบน magenta แล้วตัดออก เก็บ PNG ดิบไม่แก้ไขใน `raw/`

ขั้นเตรียมภาพด้วย PIL/NumPy/SciPy: จับช่วงสี key magenta พร้อมขอบปนสี → ตัด alpha → ลบจุดลอยขนาดเล็ก → หด alpha ด้วย MinFilter 3×3 (เข้า 1 px) → จัดกรอบเนื้อภาพเทียบ bbox โครงด้วย Lanczos → กำจัดสี key/จุดลอยจากการ resample → ส่งออก lossless RGBA ไม่มีการวาดแทนด้วยโค้ด

## จุดต่างจากสเปกและเหตุผล

1. เครื่องมือคืนสีพื้น magenta ใกล้เคียง ไม่ใช่ #FF00FF ทุกพิกเซล แม้ prompt ระบุ #FF00FF เป๊ะ จึงตัดแบบช่วงสี ไม่ใช่เทียบ RGB ตรงตัว ค่าสีมุมภาพดิบอยู่ใน `s2/verification.json` ไม่มีพื้น key ในไฟล์ส่งออก
2. ภาพดิบมี margin และสัดส่วนเนื้อภาพคลาดจากโครง จึงยืดกรอบเนื้อภาพแยกแกนเพื่อให้ bbox ตรงตามสเปก โดยไม่ตัดส่วนอาคาร ค่าแปลงจริง:

| แบบ | scale X | scale Y |
|---|---|---|
| front-one | 1.032472 | 1.132172 |
| right-one | 1.014820 | 1.048638 |
| left-two | 1.011719 | 1.007968 |
| right-two | 1.018682 | 1.012829 |

โดยเฉพาะ front-one ขยายแนวตั้งประมาณ 13.2% เทียบ crop ดิบ รูปทรงภายในจึงไม่เหมือนต้นแบบทุกพิกเซล แม้ bbox ตรง ประตู/ระเบียง/มุมกล้องตรวจด้วยภาพเทียบ ไม่ได้พิสูจน์ด้วย landmark detection ให้ Toby พิจารณามวลหลังคา/สัดส่วนเมื่อวางจริง

3. right-two รอบแรกมีลายผนังภายในที่อาจอ่านคล้ายม่านจื่อ จึงสั่ง image_gen แก้ 2 รอบ รอบแรกยังเหลือ motif จึงไม่เลือก รอบสองเปลี่ยนผนังแถบนั้นเป็นไม้เรียบแทน square grid เพื่อเอาลายเสี่ยงออกชัดเจน ช่องหน้าต่างภายนอกยังเป็นตารางปกติ คงดิบทุกครั้งพร้อม prompt และภาพ before/after ไว้ตรวจ การแก้ทั้งภาพด้วยตัววาดมีรายละเอียดเล็กน้อยนอกจุดแก้เปลี่ยนตาม จึงไม่อ้างว่า pixel-identical

4. ปลายหลังคาทองและลายประดับของผลวาดยังมีอิทธิพลจาก silhouette โซน 1 มากกว่าหลังคาจีนเรียบ ขนาด ornament/จำนวนโคม/รายละเอียดแกะหินไม่ตรงทุกจุดกับต้นแบบ ไม่มีการอ้างว่าโครงเหมือนเดิมทุกพิกเซล

## การตรวจที่รันจริง

รัน PIL ก่อนวาดเพื่อวัด references; รันขั้นตัด key/หด alpha/จัด bbox/ส่งออก และ assert ว่า decoded RGBA เท่ากับก่อน encode แบบ lossless จากนั้นรันตรวจอิสระด้วย Python/PIL อ่านไฟล์ที่บันทึกแล้วครบ 4 ภาพ ตรวจขนาด, RGBA, alpha 0–255, RIFF VP8L, bbox ทุกขอบ ±2%, ไม่มีพิกเซลสี key ที่ยังมองเห็นตามเกณฑ์ chroma ที่ใช้, SHA-256 ภาพโครงไม่เปลี่ยน ตรวจ `git status --short --untracked-files=all` และ `git diff --name-only`

พบสี key-like ที่ alpha ยังไม่เป็นศูนย์ 7 จุดใน front-one หลัง Lanczos ระหว่างเตรียมภาพ จึงเพิ่มการล้าง ringing ก่อนส่งออก ตรวจภาพ 400% พบจุดลอยใกล้ยอด right-one จึงกำจัด connected component เล็กกว่า 64 px หลัง resample และเปิดดูภาพหลักฐานใหม่

ไม่รัน unit/integration/browser/game tests เพราะงานนี้ไม่มีการเปลี่ยนโค้ดหรือเสียบ asset ไม่มีการทดสอบเดินชน/foot anchor/กลางคืน/แสดงผลในเกมจริง การตรวจสี key อัตโนมัติไม่ใช่หลักฐานว่าขอบทุกจุดไม่มี halo และไม่ใช่การตรวจวัฒนธรรมโดยผู้รับผิดชอบ
