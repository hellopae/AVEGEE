# B2-RESULT — ข้อเสนอให้คุณเป้

แนะนำเริ่มที่ **ฉากจบสรุปผล + ไอเท็ม** เพราะเกมเรามีข้อมูลรางวัลจริงอยู่แล้ว งานหลักคือทำให้ตอนชนะรู้สึกคุ้มและอ่านง่ายขึ้น

คำว่า “คะแนน” ในข้อแรกหมายถึงยอดสรุป EXP และรางวัลก่อน ในคลิปไม่เห็นคะแนนฝีมือหรือดาว และเกมเรายังไม่มีข้อมูลคะแนนการต่อสู้ จึงไม่ใส่คะแนนสมมติให้ผู้เล่น ถ้าต้องการคะแนนฝีมือจริงควรแยกใบงานกำหนดสูตรและการเก็บสถิติภายหลัง

## ลำดับความคุ้ม

คะแนนต่อไปนี้เป็นการประเมินเพื่อเลือกงาน ไม่ใช่ผลวัดความสนุกจากผู้เล่น: ผลต่อความสนุก 1–5 หารแรงทำ S=1, M=2, L=3; ทุกข้อใช้ภาพเดิมได้จึงยังไม่บวกต้นทุนวาดภาพเพิ่ม S คือปรับจุดแสดงผลจำกัด, M คือหลายส่วน/ต้องทดสอบ flow, L คือเพิ่มระบบเกมและข้อมูลถาวร

| อันดับ | ข้อเสนอ | ความสนุก ÷ แรง | CODE | ภาพใหม่จำเป็น |
|---|---|---:|---|---:|
| 1 | ฉากจบสรุปผล + ไอเท็ม | 5÷2 = 2.5 | M | 0 |
| 2 | ยอดดาเมจรวมของท่านั้น | 2÷1 = 2.0 | S | 0 |
| 3 | เน้นเป้าหมายและสถานะที่มีอยู่ | 3÷2 = 1.5 | M | 0 |
| 4 | จังหวะภาพและชื่อท่าพิเศษ | 2÷2 = 1.0 | M | 0 |

## 1. ฉากจบสรุปผล + ไอเท็ม

**ทำอะไร:** ปรับหน้ารางวัลเดิมให้เป็นตอนจบที่ชัดขึ้น ใช้ฉากหลังที่ summary ส่งมา แยกยอด EXP/เบี้ยกรรมกับช่องของที่ได้ เพิ่มตัวเลขนับขึ้นสั้น ๆ และเน้นแถวอาวุธ/พลังใหม่เมื่อได้รับจริง อ้างอิงแผงทับสนามกับยอดนับขึ้นช่วง 30.5–33.0 วินาทีใน [ref](ref.md)

**เห็นอะไรบนจอ:** หัว “ชัยชนะ — สรุปผล” ตามด้วยชื่อศัตรู EXP และเบี้ยกรรม ของที่ได้พร้อมจำนวน และปุ่ม “ไปต่อ” ขณะนับใช้ปุ่มเดียวชื่อ “แสดงยอดทันที”; กดครั้งแรกแสดงยอดสุดท้าย กดต่อจึงปิด กรณีลดการเคลื่อนไหวแสดงยอดสุดท้ายทันที ระยะนับเสนอไม่เกิน 0.8 วินาที (เป็นค่าที่เสนอใหม่ ไม่ใช่เวลาวัดจากคลิป) ไม่เพิ่มจอคั่นอีกชั้น

**ภาพใหม่:** จำเป็น 0 ชิ้น ใช้ฉากหลัง ไอคอนของ อาวุธ และพลังเดิม กรอบ/แสงทำด้วย CSS ถ้าต้องการลายเฉพาะ AVEGEE เพิ่มได้ 2 ชิ้น คือกรอบป้ายและแสงฉลอง ตาม [ART brief](draft-briefs.md#art--ภาพที่ต้องวาด) ไม่จำเป็นต้องรอภาพจึงเริ่มทำจอได้ ภาพทีมฉลองแบบคลิปยังไม่รวมในรุ่นแรก เพราะ summary ปัจจุบันไม่ได้เก็บทีมไว้

**CODE: M:** ต่อจาก openBattleReward เดิม รักษาการจ่ายของ คิวเรื่องราว และปุ่มปิดทุกทาง ต้องทดสอบศึกหลายระลอก/เลื่อนขั้น/final encounter/receipt ไกด์

## 2. ยอดดาเมจรวมของท่านั้น

**ทำอะไร:** เพิ่มข้อความ “รวม N” ตอนโจมตีหลายเป้าหมาย โดยรวมเฉพาะ damage จาก hits ของแอ็กชันนั้นครั้งเดียว ไม่รวมดาเมจสวน/ฮีล ไม่เปลี่ยนสูตรโจมตี อ้างอิงคำ Total ที่ [12.0 วินาที](ref-frames/combat-03.png)

**เห็นอะไรบนจอ:** เลขเดิมยังขึ้นที่แต่ละเป้าหมาย แล้วมียอดรวมสั้น ๆ หนึ่งตำแหน่งเมื่อจบท่า ใช้เฉพาะท่าที่มีหลาย hit/หลายเป้าเพื่อลดความรก กรณี hit เดียวไม่ต้องเพิ่มข้อความซ้ำ

**ภาพใหม่:** 0 ชิ้น ใช้ตัวอักษรกับ CSS เดิม **CODE: S** ขอบเขตคือผลรวมต่อหนึ่งแอ็กชันจากข้อมูล hits เดิม ไม่ใช่สถิติดาเมจทั้งศึกหรือระบบคอมโบ หากต้องเก็บต่อเนื่องข้ามเทิร์นจะเกินขอบเขต S

## 3. เน้นเป้าหมายและสถานะที่มีอยู่

**ทำอะไร:** ให้ศัตรูที่เลือกมีขอบชัด และแสดงชื่อสถานะจาก state จริงใกล้ตัว เช่น สะกดจิต/เผาไหม้ ใช้แรงบันดาลใจจากขอบสว่าง ดาวรอบหัว และ STAGGERED ที่ [2.0 วินาที](ref-frames/combat-01.png) เลือกปรับการแสดงผล ไม่เพิ่มกฎ stagger ใหม่

**เห็นอะไรบนจอ:** แตะศัตรูแล้วรู้ทันทีว่าท่านี้เล็งใคร ชื่อสถานะเป็นข้อความไม่พึ่งสีอย่างเดียว เมื่อศัตรูตาย/เปลี่ยนเป้า ขอบและชื่อย้ายตาม state โดยไม่ทิ้งป้ายค้าง มือถือหลีกเลี่ยงวางป้ายทับ HP

**ภาพใหม่:** 0 ชิ้น ขอบและป้ายทำด้วย CSS **CODE: M** เพราะต้องรองรับหลายตัว ระลอกใหม่ และตำแหน่งหลังกล้องแปลงพิกัด เกมเรามี selectedFoeId และเอฟเฟกต์สถานะอยู่แล้ว งานนี้ปรับความชัดจากระบบเดิม

## 4. จังหวะภาพและชื่อท่าพิเศษ

**ทำอะไร:** ปรับ cue ของท่าแรงที่มีอยู่ให้มีชื่อท่าสั้น ๆ และจังหวะปะทะตรงภาพ ใช้แสงปะทะช่วง [9.0](ref-frames/combat-02.png) กับแถบ Thundaga Blade ที่ [26.0](ref-frames/combat-04.png) เป็นตัวอย่าง ส่วนซูม/แพนใช้ระบบกล้องของเราเดิม ไม่อ้างว่าคลิปนี้พิสูจน์การซูมตอนท่าไม้ตาย

**เห็นอะไรบนจอ:** ชื่อท่าโผล่ช่วงเริ่ม ผู้ใช้ท่ากับเป้าหมายยังอยู่ในจอ แสงปะทะจบแล้วคืนกล้อง ปุ่มและ HP ไม่ขยายตามฉาก เปิดลดการเคลื่อนไหวแล้วยังอ่านชื่อท่าได้

**ภาพใหม่:** 0 ชิ้น ใช้เอฟเฟกต์เดิมกับแถบ CSS **CODE: M** ต้องคุมจังหวะ hit และการยกเลิกตอนศึกจบ ไม่สร้างฉากคัตซีนท่าไม้ตายใหม่ ไม่เปลี่ยน damage การทดสอบกล้องเดิมมี reduced motion และ impact ครั้งเดียวให้ต่อยอด

แนะนำส่งข้อ 1 เป็นงานถัดไปก่อน ข้อ 2–4 แยกใบงานได้ ไม่ผูกให้ต้องทำพร้อมกัน หลักฐานและช่องว่างทางข้อมูลดู [gap.md](gap.md)
