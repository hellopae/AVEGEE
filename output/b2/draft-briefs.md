## ART — ภาพที่ต้องวาด

**รุ่นแรกไม่จำเป็นต้องวาดภาพใหม่: 0 ชิ้น** ใช้ background จาก summary, `img/ui/icon-coin.png`, itemImg, weaponImg และ ABILITY_FX เดิม ไม่คัดลอกตัวละคร/ฉาก/ตรา/ไอคอนจากวิดีโอ

ถ้าคุณเป้เลือกตกแต่งเพิ่มเติม เสนอ ART 2 ชิ้นต่อไปนี้เป็นแพ็กเสริม ไม่ใช่เงื่อนไขบังคับของ CODE:

| ชิ้นงานเสนอ | จำนวน | ขนาดส่งออก pixel | รายละเอียด / พื้นที่ปลอดภัย |
|---|---:|---|---|
| กรอบป้ายฉลอง AVEGEE | 1 | 1024×256 PNG RGBA โปร่งใส | ลายกรอบโทนเกม เว้นกลางอย่างน้อย 720×128 ให้ข้อความ HTML วางทับ ไม่ฝังคำว่าชนะหรือภาษาใดในภาพ; ใช้แสดง 512×128 บนจอใหญ่ และย่อให้พอดีเนื้อหามือถือ |
| แสงฉลองหลังป้าย | 1 | 512×512 PNG RGBA โปร่งใส | ประกายอ่านง่าย ขอบค่อย ๆ โปร่ง ไม่บังตัวอักษร ใช้ภาพเดียวขยับ opacity/scale; เปิดลดการเคลื่อนไหวให้เป็นภาพนิ่งหรือซ่อน |

ไม่ต้องวาดฉากหลังใหม่ ไม่ต้องวาดไอเท็มใหม่ ไม่รวมท่าฉลองรายตัวละคร หากต้องการทีมยืนแบบคลิปให้แยกใบงานตรวจรายชื่อตัวละครและ sprite ก่อนประเมินจำนวนภาพ ห้ามประเมินเหมารวมว่ามีท่าฉลองพร้อมทุกตัวแล้ว

จุดตรวจรับ ART เสริม: เปิดได้ตรงขนาด, alpha โปร่งจริงไม่มีพื้นหมากรุกติดภาพ, เมื่อนำไปวางที่ 358px ยังอ่านหัวเรื่องได้, ไม่มีข้อความ/จำนวนรางวัลฝังในรูป งานเอกสารครั้งนี้ไม่ได้สร้างภาพ ART เหล่านี้

## CODE — ขั้นตอนที่เสนอ

**ขนาด M** ปรับ presentation ของ pendingReward เดิม ไม่เปลี่ยน balance และไม่เพิ่มสถิติทั้งศึก

1. อ่านทางสร้าง `B.summary` ใน declareWin (`src/game.js:3600` เป็นต้นไป), `endBattle` (`3974`), `openBattleReward` (`src/ui.js:5790`) และ dispatcher (`5996`–6030) ก่อนแก้ กำหนดให้ data source เป็น receipt เดิม ห้ามคำนวณหรือจ่ายเงิน/EXP/item จาก animation
2. แยกการจัดแสดงยอด/ไอเท็มออกจากการยืนยันปิด ให้อ่าน `kind, who, zone, background, coin, exp, items, weapons, abilities` พร้อมรองรับ receipt พิเศษ `title, description, guideZone, encounter` ที่ผู้เรียกใช้อยู่ คงข้อความเฉพาะของไกด์และขั้นตอน acknowledgeFinalReward
3. ปรับ layout กล่องเดิมเป็น 2 คอลัมน์ที่ 1280 และคอลัมน์เดียวที่ 390 ตาม wireframe ใช้ชื่อจริงผ่าน i18n และ helper ภาพเดิม กรณีไม่มี background ใช้ fallback เดิม รายการจำนวนมากต้องเลื่อนอ่านได้ ปุ่มคงอยู่ในพื้นที่มองเห็น ไม่มี horizontal scroll
4. เสนอจังหวะหลังเปิด: หัว/ยอด/รายการครบอ่านได้ทันที → นับเลขเฉพาะ EXP/coin 0 ถึงค่าจริงไม่เกิน 800ms → ค้างยอดสุดท้าย แสงตกแต่งแยกจากตัวเลข ไม่ยืดเวลาปิด UI และไม่แปลง EXP เป็นคะแนนฝีมือ รายการไอเท็มต้องเห็นจำนวนจริงตั้งแต่แรก ไม่สุ่ม animation ให้ดูเหมือนได้เพิ่ม
5. ระหว่างนับใช้ปุ่ม “แสดงยอดทันที”; เมื่อจบเปลี่ยนเป็น “ไปต่อ” การกดข้ามนับเปลี่ยนเฉพาะ display ครั้งถัดไปจึง acknowledge/ปิด × และ Esc ปิดตามเส้นทางเดิม ไม่เรียก grant เพิ่ม; screen reader รับยอดสุดท้ายครั้งเดียว ไม่ประกาศทุกเฟรม
6. เคารพ prefers-reduced-motion โดยแสดงยอดสุดท้ายทันที ยกเลิก timer/listener เมื่อปิดหรือ receipt เปลี่ยน และใช้ guard ของ dialog รุ่นเดิม ป้องกัน close ของฉากสู้มาปิดสรุปรางวัลตัวใหม่
7. คงลำดับ flow แยกตามชนิด: ศึกทั่วไปเรื่องราวก่อนสรุป, final encounter สรุปก่อนเรื่องราวถัดไป; คง afterReward และ pendingLevel/discovery ไม่เพิ่มหน้าสรุปใน soul/lose/flee ทดสอบไกด์ที่ใช้หน้ารางวัลร่วมกัน
8. ระยะแรกไม่ต้องเปลี่ยน save schema หรือแตะ battle-turns เพราะ round เดิมไม่ใช่ผลรวมทุก wave หากเพิ่มคะแนน/ดาว/เวลา/maxDamage ในอนาคตให้แยกงาน data capture กับนิยามคะแนนก่อน

ไฟล์ที่คาดว่าใบงาน CODE ในอนาคตต้องแตะ: `src/ui.js`, style หน้ารางวัลใน `index.html`, `src/i18n.js` และ tests ที่เกี่ยวข้อง; `src/game.js` แตะเฉพาะเมื่อพบข้อมูลที่จำเป็นจริงหลังทบทวน สิ่งนี้เป็นขอบเขตงานถัดไป ไม่ใช่การแก้ไฟล์ในงานเอกสารปัจจุบัน

## ผลตรวจประกอบเอกสารครั้งนี้

- `ffprobe` ตรวจ metadata และ `ffmpeg` ตัด contact sheet, เฟรมสู้ 4 ภาพ, เฟรมท้าย 13 ภาพใน `ref-frames/`; เปิดดูภาพรวมและภาพหลักที่อ้างเพื่อเทียบลำดับ
- รัน `node --test tests/border-owner-flow.test.mjs tests/battle-turns.test.mjs tests/battle-camera.test.mjs tests/boss-guides.test.mjs` ได้ 40 tests, fail 0, skip 0 (exit 0)
- รัน `node --test tests/balance28b.test.mjs tests/g3b-frontier-challenge.test.mjs tests/b2b-final-event.test.mjs tests/acquisitions29a.test.mjs` ได้ 56 tests, fail 0, skip 0 (exit 0)
- รวมสองคำสั่ง 96 tests ไม่มี failure ผลนี้ครอบคลุมโค้ดปัจจุบันตามชุดที่ระบุเท่านั้น
- Node แจ้ง ExperimentalWarning เรื่อง localStorage ไม่ได้ระบุ `--localstorage-file`; การตรวจเหล่านี้ไม่ใช่การเปิดเกมใน browser จริง
- ไม่ได้ทำ browser/layout test ของแบบเสนอ เพราะไม่มีการ implement UI ในงานนี้ และไม่รับรอง QA ของแบบเสนอ
