## วิธีอ่านผลพิกัด

พิกัดเป้าหมายมาจาก `DUNGEON_CORRIDOR` ใน `src/route-geometry.js` (อ่านอย่างเดียว) ตรงกับ guide ของ Toby; ทุกค่าปกติอ้างมุมซ้ายบนของภาพ ช่วง 0–1. จุดจริงในตารางเป็น **การกะศูนย์แถบปูหินด้วยสายตา** จากภาพและ overlay ไม่ใช่ segmentation หรือพิกัดที่วัดได้อย่างแม่นยำ; หลัง cleanup ตรวจ overlay ซ้ำ รูปทรงทางยังใกล้เคียงเดิมและคงจุดกะภาพเดิม; ความไม่แน่นอนประมาณ ±10–15 px โดยเฉพาะทางโค้ง/สะพาน จึงไม่ใช้ตารางนี้รับรอง tolerance ทั้งเส้น. ## สิ่งที่ยังไม่ตรง / ข้อจำกัด

- จุด **7–11, 13, 15–17** ยังคลาดศูนย์ถนนเกิน ±0.015 โดยประมาณ (9 จาก 31 จุด); โดยเฉพาะโค้งขึ้นจาก CP0 และโค้งขวาบริเวณป้อม. จุด 16–18 อยู่ใกล้ราวด้านใน ภาพยังไม่ควรใช้เป็นหลักฐานว่าเดินได้เต็ม strip.
- ความกว้างถนนขั้นต่ำ ±0.026 และวงรีทั้งวง **ยังยืนยันไม่ได้ครบ**: START มีราวหน้าลานกินขอบ, CP0 มีราว/ขอบผาใกล้ขอบวงรี, CP2 มีราวหน้าลานแตะบริเวณล่างของวงรี; ไม่ถือว่าจุดศูนย์อยู่บนหินแล้วแปลว่าลานเต็มขนาด.
- Layout ต้นทางครอบคลุมศูนย์ 31/31 จุด แต่ภาพที่วาดยังไม่ตรง layout ทั้งหมด แม้ซ่อมแล้วสองรอบ. ไม่ได้เปลี่ยนพิกัดโค้ดเพื่อให้เข้ากับภาพ.
- ภาพสไตล์/กล้อง/แสงประเมินด้วยสายตา: เป็น painterly มุมสูงเฉียง มีรายละเอียดหนาแน่นและแสงอุ่นซ้ายบนตามต้นแบบ แต่ไม่ได้อ้างว่าเข้าชุดกันเป๊ะในเชิงการวัด.
- ไม่มี runtime/gameplay test เพราะใบนี้วาดภาพเท่านั้น และไม่ได้เปิดใช้งาน route หรือแก้โค้ด.

## การตรวจที่รันจริง

1. PIL วัดขนาด/mode ของต้นแบบ guide และภาพธีม: ต้นแบบและ guide 1672×941 RGB; รายละเอียดอยู่ measurements.json.
2. ตรวจ layout สะอาดด้วย PIL ว่าจุดศูนย์ทั้ง 31 อยู่บนแถบสีถนน: 31/31. นี่คือการตรวจ reference เท่านั้น.
3. Export WebP q96 แล้ว PIL เปิดอ่านกลับและ assert ขนาด 1672×941 / mode RGB พร้อม decode; PSNR จาก PNG ต้นทางถึง WebP 37.46 dB ใช้วัดการบีบอัดเท่านั้น ไม่วัดความตรงของงานวาด. เปิดภาพขยาย [ด่านใน](f23/qa/inner-gate-detail.png) และ [EXIT](f23/qa/exit-detail.png) ตรวจซ้ำหลังเก็บธง.
4. วาด overlay และอ่านจุดภาพจริง 31 จุดด้วยสายตา คำนวณ Δ ต่อแกน; ผลคลาด/ไม่แน่นอนระบุด้านบน.
5. ตรวจ SHA-256 ภาพอ้างอิงเดิมและ git diff/status เพื่อยืนยันขอบเขตไฟล์; ไม่รัน application tests เพราะไม่มีการแก้โค้ด.
