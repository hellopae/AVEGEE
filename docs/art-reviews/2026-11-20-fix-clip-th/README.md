แก้เฉพาะ `img/crew-combat-v1/th/boon.webp` และ `guard.webp` โดยใช้ **ImageGen ในตัว 5 ครั้ง** เลือกใช้ผล 4 ภาพ อีกภาพของกุมภัณฑ์เซลล์ 5 ไม่เลือกเพราะหัวกระบองเล็กเกินไป ไม่มีการใช้ผู้ให้บริการสร้างภาพอื่น

## เซลล์ที่พบและแก้

นับเซลล์ **1–8 ซ้ายไปขวา แถวบนก่อน** พิกัดทั้งหมดในตารางเป็นพิกัดภายในเซลล์ เริ่มที่ 0 ตรวจเส้นขอบด้วย alpha > 127 และดูภาพบนพื้นสีทึบประกอบ ไม่ใช้สี RGB ที่ซ่อนอยู่ใต้ alpha=0 เป็นเนื้อภาพ

| ภาพ / เซลล์ | หลักฐานเดิม | การซ่อม | ขอบตรงยาวสุดในบริเวณตรวจ เดิม → ใหม่ |
|---|---|---|---|
| บุญ 5 (แถว 2 คอลัมน์ 1) | ปลายมือ/ดอกบัวด้านขวา x=364, y=270–331 | หดปลายแขนและชายแขนเสื้อเล็กน้อย ให้เห็นมือประคองดอกบัวครบ | 62 → 9 px |
| กุมภัณฑ์ 3 (แถว 1 คอลัมน์ 3) | อาวุธขาดด้านซ้าย x=19, y=214–280 | ยกมุมกระบองเข้าด้านใน ให้หัวกระบองอยู่เหนือซ้ายของไหล่และเห็นปลายครบ | 67 → 11 px |
| กุมภัณฑ์ 5 (แถว 2 คอลัมน์ 1) | หัวกระบองด้านขวา x=364, y=333–413 | ปรับช่วงด้าม/มุมหัวกระบองให้หดเข้ามา หัวกระบองสีเทาดำและขอบทองครบ | 81 → 12 px |
| กุมภัณฑ์ 6 (แถว 2 คอลัมน์ 2) | ขอบหัวกระบองแตะเส้นตัด x=364, y=209–217 | ขยับมุมส่วนหัวและด้ามบนเข้าด้านใน ให้เห็นเส้นรอบหัวครบ | 10 → 8 px |

ขอบตรงสั้นเป็นส่วนหนึ่งของเส้น pixel art ได้ ตัวเลขข้างต้นจึงเป็นหลักฐานตำแหน่งประกอบการดูภาพ ไม่ใช่ตัวตัดสินความครบของมือ/อาวุธโดยลำพัง สำหรับเซลล์ 6 เส้นที่ x=364 ยาว 9 px ส่วนเส้นข้างเคียงยาวสุด 10 px

## วิธีประกอบและการรักษาจุดยืน

ImageGen วาดส่วนที่ขาดจากภาพอ้างอิงของแต่ละเฟรม จากนั้นนำผลกลับสู่พิกัดเซลล์ 384×512 และเลือกประกอบเฉพาะบริเวณมือ/แขนเสื้อหรืออาวุธ ไม่ย่อทั้งตัว ไม่แทนที่หัว ลำตัว ขา หรือเท้าทั้งเฟรม ภาพกุมภัณฑ์เซลล์ 3 เลื่อนชิ้นซ่อมไปขวา 7 px เพื่อเว้นขอบซ้าย พื้นที่เลือกประกอบแสดงเป็นพิกัด polygon ใน `verify.py`

บันทึก sheet เป็น WebP แบบ lossless พร้อม alpha และเก็บ RGB ใต้พิกเซลโปร่งใส เพื่อให้พิกเซลเดิมนอกส่วนซ่อมเทียบกลับได้ตรงกัน ไม่เปลี่ยนชื่อ ลำดับเฟรม หรือตำแหน่งเซลล์

| เฟรมที่แก้ | ระยะโปร่งใสซ้าย / ขวา หลังแก้ (alpha=0) | ขอบล่างสุดเดิม → ใหม่ | การเลื่อนจุดเท้า x / y |
|---|---|---|---|
| บุญ 5 | 56 / 25 px | 485 → 485 | 0 / 0 px |
| กุมภัณฑ์ 3 | 7 / 47 px | 485 → 485 | 0 / 0 px |
| กุมภัณฑ์ 5 | 27 / 10 px | 486 → 486 | 0 / 0 px |
| กุมภัณฑ์ 6 | 32 / 11 px | 486 → 486 | 0 / 0 px |

ตรวจพิกเซล RGBA ทั้งแถบเท้าเท่าต้นฉบับทุกจุด: y=400–511 ยกเว้นกุมภัณฑ์เซลล์ 5 ใช้ y=431–511 เพราะหัวกระบองอยู่ถึง y≈419 และรองเท้าอยู่ต่ำกว่าแถบเริ่มดังกล่าว เซลล์ 7 ที่ยกเท้าขึ้นไม่ได้แก้ทั้งเซลล์ จึงรักษาเท้าที่ยกไว้ด้วย ชุดพิกัด x ของพิกเซลในสามแถวล่างสุดและค่า y ล่างสุดตรงเดิมทุกเซลล์ ดูตัวเลขเต็มใน `checks.json`

## ตรวจ idle และข้อสังเกตนอกมือ/อาวุธ

ตรวจ `boon-idle.webp` และ `guard-idle.webp` ครบทั้ง 4 เฟรมต่อไฟล์แล้ว ไม่พบมือหรืออาวุธขาด จึงไม่แก้ ทั้งคู่คงไฟล์เดิมทุกไบต์ ขนาดจริงของ idle คือ **1024×384, 4×1 เซลล์ละ 256×384** ไม่ใช่ขนาด combat

ยังมีการตัดลำตัวด้านซ้ายของกุมภัณฑ์เซลล์ 4 และส่วนเท้าของเซลล์ 3/7 ในต้นฉบับ รอบนี้รักษาบริเวณเหล่านั้นไว้ตามข้อกำหนดจุดเท้าและขอบเขตซ่อมมือ/อาวุธ ไม่ได้อ้างว่าความผิดปกติอื่นของ sheet ถูกซ่อมทั้งหมด

```sh

git diff --check
```

สคริปต์ตรวจไฟล์ที่บันทึกจริงจบด้วย exit code 0: ทั้งสอง combat เป็น RGBA 1536×1024, เซลล์ละ 384×512; เปลี่ยนเฉพาะ 4 เซลล์ที่ระบุและภายในบริเวณซ่อม; พิกเซลเท้าไม่เปลี่ยน; combat ทั้ง 16 เซลล์มีขอบโปร่งใสอย่างน้อย 6 px; idle ไม่เปลี่ยนทุกไบต์ ตรวจด้วยตาทั้ง 16 เฟรม combat และ 8 เฟรม idle รวมทั้งภาพเทียบแล้ว ไม่มีการรันเกมหรือรับรองผล animation ใน engine
