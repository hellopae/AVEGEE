## ชั้นภาพและพิกัด

`manifest.json`: world, tiles, layers, liquids, layerOrder และตำแหน่งทุกชั้น พื้นมี 19 tiles ขนาดภายในไม่เกิน 512 px ทั้ง PNG และ WebP lossless มี gutter 2 px (ตัดที่ขอบ atlas) ต้องใช้ `crop` ใน manifest ก่อนวาง `rect` อย่าเอา gutter มาต่อเป็นพื้น

Sky ใช้ของโซน 1 · ฉากไกลซ้าย crop ภูเขาไฟโซน 1 พร้อมขอบ alpha ไล่จาง · ขวาวาดภูเขาเอเชียหมอกใหม่ RGBA · ลาวาจากภาพ pure-fluid ต้นฉบับที่ใช้สร้าง flows โซน 1 · น้ำ/น้ำตก crop เฉพาะของเหลวจาก `fluid-master.png` โซน 2 แล้วลดสีฟ้าอิ่มจัด แยกจากหินและพื้นทุกชั้น

พื้นเกิดจากฐานร่วมหนึ่งภาพและรายละเอียดซ้อนทับสองส่วน ไม่ได้สร้างแต่ละ tile แยกกัน ยืนยันตำแหน่งรายละเอียดด้วย SIFT/RANSAC 142 และ 150 inliers ล็อก alpha ของฐานร่วมทั้งหมด ปกป้องบันไดและขอบ silhouette ก่อนผสม RGB

ImageGen เดิมให้เนื้อพื้น alpha ประมาณ 251–254: ก่อนล็อกฐาน ปรับเฉพาะส่วน alpha ≥230 เป็น 255 และค่าฝุ่น <12 เป็น 0 โดยรักษารูปร่างช่องสะพาน/ร่องของเหลว ไม่เติมพื้นลงช่องเหล่านั้น เพิ่มขอบโปร่งใสด้านบน 176 px ก่อนขยาย 1.5 เท่า พิกัดจาก guide เดิมจึงเป็น `atlas = guide × 1.5 + [0,264]`

`layout.json` มี 22 ตำแหน่ง / 10 sprite: ถ้ำ back/front, ประตูไทย world-kit, ประตูเอเชีย sprite เกม `img/map-v5/st-frontier-asia.webp`, เมเปิลแดง สน ต้นไม้เหลืองเปลี่ยนโทน หินบะซอลต์/มอส และเสาโคมทอง ใช้คลังเดิมก่อนวาดเพิ่ม ทุกชิ้นมี `id,sprite,x,y,w,h,flipX,foot,layer,category` และ `preview` สำหรับหน้ากล้อง

`foot` เป็นพิกัด **ภายในกรอบวางขนาด w×h**; บวก x,y จะได้ `footWorld` ใน atlas ไม่ใช่พิกัดใน PNG ต้นฉบับ ถ้ำทั้งสองชั้นใช้กรอบและ foot เดียวกัน `cave-back` ถือผนังด้านใน/ส่วนหินด้านหลัง พื้นมืด และธรณีประตู; `cave-front` ถือหน้าผู้พิทักษ์ ซุ้ม เสาข้าง และกระถางไฟ พิกเซลสองชั้นไม่ซ้อนเจ้าของ ประกอบกลับตรงต้นฉบับทุกพิกเซล จัดตัวละครระหว่างสองชั้นเมื่อประกอบเกม

## ผลตรวจและข้อไม่แน่ใจ

- วัดทุก segment ของเส้นหลัก หน้าถ้ำ และสะพานทั้งสอง ไม่ใช่แค่จุดหัวท้าย มีทั้ง alpha centerline, Euclidean distance ถึง alpha<250 และตรวจทุกพิกเซลภายในแนวกว้าง 80 px สมมติความกว้างตัวละคร 36 px ×2 พร้อมช่องว่าง 8 px ค่าต่ำสุดบน centerline ทุกเส้นเป็น alpha 255
- alpha ของหน้าผาก็ทึบเช่นกัน ผลนี้จึงยืนยันเฉพาะความทึบ/ระยะถึงขอบภาพตามแนวที่ลากบนพื้นด้วยตา **ไม่ยืนยันว่าเดินได้จากระบบเกม** ต้องสร้าง semantic walkmask, collision, depth sorting, สเกลตัวละครจริง และตรวจทางออกของสะพานก่อนนำเข้าเกม
- ของเหลว 3 ชุด ชุดละ 12 เฟรมที่ต่างกัน มี alpha คงที่ เคลื่อนตามแนวไหลด้วย periodic crossfade ไม่มีหิน/ต้นไม้/อาคารใน texture `flow-review.json` บันทึกความต่างระหว่างเฟรมรวมรอยวน 11→0 และตัวอย่าง 3 รอบ ภาพเคลื่อนไหวตรวจมี 36 เฟรม
- **ยังไม่ได้คลิกตรวจในเบราว์เซอร์จริง**: `cua.createBrowserTab` ตอบ `The browser access host is unavailable` ไม่ได้เปิดเกมหรืออ้างผลตรวจอุปกรณ์จริง
- `preview-code-review.json` รัน JavaScript ที่ส่งออกจริงด้วย file-backed fetch และ DOM/canvas จำลอง: ซูม 2 ระดับ, tile 19→8, เลื่อนกล้อง, เปิดปิดพื้น, เล่น/หยุด, หยุดครบ 3 รอบ และ viewport 390×500 ใช้งานได้ใน harness ไม่โหลด atlas เต็มหรือ PNG วัตถุต้นฉบับ ไม่แทนผล render/browser/mobile จริง

## ทำซ้ำ / ตรวจไฟล์

```sh
python3 scripts/export-border12-terrain.py
python3 scripts/build-border12-redraw-pack.py
python3 scripts/verify-border12-redraw.py
node scripts/check-border12-preview.mjs
```

Exporter ดัดแปลงจาก `export-seamless-terrain.py` โซน 1 ตามใบงาน แก้เฉพาะ script ใน worktree นี้ ต้นทางคลังภาพอ่านอย่างเดียว `build-border12-redraw-pack.py --source-root /path/to/docs/art-reviews` เปลี่ยนที่อยู่คลังต้นทางได้ เก็บเฉพาะ generated masters ที่ pipeline ใช้จริงพร้อมไฟล์ส่งออก ไม่มี draft เก่าหรือ zip ซ้ำ ไม่แก้ `src/`, `tests/`, `index.html` ของเกม และไม่มี commit/push/merge/deploy

## ImageGen ledger

รอบนี้ **5 ครั้ง** ใช้ built-in `image_gen.imagegen` เท่านั้น: พื้น 1, รายละเอียด 2, ภูเขาเอเชีย 1, ถ้ำ 1 ทุกครั้งแนบภาพโซน 1 ฉบับย่อเป็น style reference ไม่มี Shado, CLI หรือ API fallback คำสั่งเต็มและไฟล์ผลลัพธ์อยู่ `generation-prompts.json`
