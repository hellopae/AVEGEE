## วิธีประกอบ

อ่านต้นทางอย่างเดียวจาก worktree ตามใบงาน มี4 native ของแต่ละchunk (แถว4มี2ส่วน) รวม70 native โดยไม่นับ t31 ของ plaza ซึ่งเป็นการทดลอง3× ใช้69ภาพและfallbackแทนr4-c1/q12อีก1ส่วน แปลง schema ของ registration ทุกชุดเป็นพิกัด master1× และตรวจว่า matrix global ตรงกับ matrix context บวกorigin ก่อน warp native ตรงไป2× ด้วย Lanczos4 ไม่มี downsample/upscale ระหว่างทาง

ประกอบส่วนย่อยพร้อม context64 map px แล้วประกอบ chunk ข้าม run บนช่วง overlap128 map px ใช้ squared RGB difference + Gaussian5 หา min-cost path ก้าว -1/0/+1; feather smoothstep±8 output px ใช้การชดเชยสนามสีเฉพาะแถบ overlap แบบสมมาตร Gaussian16 output px จำกัดด้านละ8ระดับRGB และ taperเป็นศูนย์ที่ขอบ ไม่ใช้ broad colour correction ของสคริปต์ HD-FULL ไม่ปรับสีทั้งภาพ ไม่ sharpen ไม่ DOF/parallax และไม่มี local deformation

เส้นทางภายในnative50เส้น ข้ามคอลัมน์16เส้น ข้ามแถว3เส้น รวม69เส้น ตามด้วยขอบ fallback เฉพาะโครงสร้าง24เส้น รวม93เส้น ขอบ fallback ใช้ min-cost หาmask4ด้านร่วมกับ feather±8 output px โดยผสมสีต้นฉบับตรง ๆ ไม่มีการชดเชยสีเพิ่ม เนื้อภาพนอกวงแหวนไม่ได้เปลี่ยนจากขั้นตอน fallback

ตัดไฟล์ส่งออกจาก masterเดียวกันในหน่วยความจำ แล้วตรวจจาก WebP lossy ที่ decode กลับมาใหม่ ไม่เก็บmasterซ้ำและไม่จำเป็นต่อ verify

## Fallback ตามจริง

ImageGen ใน run ประกอบนี้ **0 ครั้ง** ไม่มีการวาดใหม่ ไม่มี native ที่หาย แต่มีต้นทางที่รูปทรง/รายละเอียดค้างแก้ จึงใช้ **v5 + runtime repairs ขยาย2× Lanczos** ในส่วนต่อไปนี้ เก็บเนื้อเดิมเพื่อรักษารูปทรง ไม่ถือเป็นรายละเอียด native2×

1. **r4-c1/q12** core `[512,3072,512,205]` แบบ `[x,y,w,h]`: HD-FULL-8 `manual-review.json` ระบุว่าป่าด้านล่างถูกเปลี่ยนเป็นพื้นโดยผิดข้อกำหนด ใช้ fallback รวมcontextของpartนี้ แล้วเข้ารอยต่อกับnativeข้างเคียง
2. **สะพานสวรรค์** core `[3620,545,4065,745]`: รูปเสา/หัวสะพานและหินกลางน้ำเปลี่ยน ต้นทางวัดคลาด5–12px
3. **บันไดลาวาเหนือ** core `[570,800,750,940]`: แนวข้าง/ชานบันไดเปลี่ยน
4. **บันไดลาวากลาง** core `[620,1420,820,1620]`: ความกว้าง/ขอบชานเปลี่ยน
5. **บันไดลาวาล่าง** core `[700,1960,825,2050]`: มุมบนซ้ายคลาด `[9,5]` px และภาพตรวจเห็นความกว้างเปลี่ยน
6. **บันไดลานใต้** core `[2420,2910,2620,3060]`: ขอบบันไดคลาด7pxและ silhouetteราวเปลี่ยน
7. **บันไดท่าเรือ** core `[2770,2120,2960,2240]`: แนวข้าง/ราวเปลี่ยนและจุดจับคู่คลาด10px

รายการ2–7 ใช้รูปแบบ `[x0,y0,x1,y1]` หน่วยmap1× เพิ่มวงแหวนcontextข้างละ48px แล้วตัดต่อด้วยmin-cost4ด้าน พิกัดจริงและจำนวนพิกเซลที่ใช้ใน `inventory.json` ภาพเดิมบางบริเวณมีราว/ต้นไม้/เงาหรือพร็อพที่nativeต้นทางลบไป สิ่งเหล่านี้อาจกลับมาในfallback และความคมของfallbackต่ำกว่าส่วนnative ต้องตรวจ spriteซ้ำตอนบูรณาการเกม ไม่กล่าวว่าการลบวัตถุของทุกrunได้รับการรับรอง

## ผลตรวจและข้อค้าง

ตรวจจำนวนภาพ ขนาด decode hash และงบจากไฟล์จริงด้วย `scripts/verify.py` ผลล่าสุดให้อ่าน `verification.json` และ `structure.json` ไม่มีการใช้ inlier residual ของSIFTอ้างแทนความถูกต้องของรูปทรง

โครงสร้างใช้ DoG sigma1.5/6, template49×49, NCCค้นหา±12map px; รายงานจุดที่confidence≥0.6และจุดกำกวมทั้งหมด ตรวจlandmarkจากแต่ละrunซ้ำกับภาพสุดท้าย และเพิ่มจุดทุก80pxตามcontourที่decodeจากRLEของ `src/town-walkmask.js` การซ่อม6จุดเลือกจากผลวัดและภาพก่อนซ่อม จึงไม่ใช่การทดสอบอิสระจากการตัดสินใจซ่อม

walkmaskเซลล์8world units มีขนาดประมาณ10.24map px และอิงภาพv2 จึงช่วยอ้างอิงเส้นทาง แต่พิสูจน์ขอบsemanticละเอียด4pxทั้งแผนที่ไม่ได้ จุดจับคู่ภาพที่เกิน4pxอาจเป็นขอบที่ผิดจริงหรือtexture/วัตถุที่ถูกลบ จึงไม่ตัดจุดเหล่านั้นทิ้งเพื่อทำตัวเลขให้ผ่าน ไม่ใช้ผลsharpnessเป็นตัวคูณความละเอียดทางสายตา

รอบหลังซ่อม: **1,613จุด; จับคู่ได้1,087; กำกวม526; เกิน4pxอยู่7จุด ค่าสูงสุด5px** (ก่อนซ่อม34จุดเกิน4px) จุดค้างในพิกัดmap1×: `[2490,880]`, `[2438,849]`, `[2477,869]` ลานชั้นบน, `[578,2007]` หินฝั่งลาวา, `[2867,2855]`, `[2878,2847]` ขอบลานใต้ตะวันออก, `[4670,701]` ขอบลานน้ำแข็ง ไม่แทนบริเวณเหล่านี้ด้วยภาพเบลอเพิ่มเพียงเพื่อให้ตัวเลขผ่าน เพราะการจับคู่บางจุดอยู่บนลายหิน/ใบไม้ที่เปลี่ยนไป; เก็บผลทุกจุดให้ตรวจต่อ

การตรวจภาพofflineทั้ง7แถบไม่เห็นเส้นตรงเป็นตารางchunkเด่นชัด แต่เห็นการเปลี่ยนความคมที่fallbackบันไดลาวาล่าง ท่าเรือ บันไดลานใต้ และป่าr4-c1/q12 จึงไม่รับรองว่าไม่มีรอยต่อที่ซูมเกมทุกตำแหน่ง หลักฐานก่อนซ่อม6บริเวณใน `fallback-check/before-*.jpg` เป็นภาพเปรียบเทียบv5|nativeประกอบเดิมที่2×map ไม่ใช่ภาพทดสอบในเกม

**เกณฑ์1:** ตรวจเชิงไฟล์ครบ20ชิ้น+preview+manifest และ≤40MB

**เกณฑ์2:** ยังไม่ยืนยันทั้งข้อ ต้องพิจารณาจุดคลาด/กำกวมใน `structure.json` และรอยต่อจริงที่ซูมเกม เอกสารนี้ไม่รับรองstructure≤4pxทุกแนวหรือไม่เห็นรอยต่อในเกม แม้มีภาพตรวจเต็มความยาวครบ7เส้นแล้ว ขอบfallbackมีความต่างของความคมที่อาจสังเกตได้ และลวดลายหิน/ใบไม้ตรงmin-cost cutอาจขาดช่วง บันทึกตรวจภาพเพิ่มเติมใน `visual-review.json`

**เกณฑ์3:** ระบุfallback7ส่วนและข้อค้างข้างต้น; ไม่มีImageGenในrunนี้

## คำสั่งตรวจซ้ำ

ต้องมี Python3, Pillow, numpy และ OpenCV; รันจากrepo root:

```sh
python3 docs/art-reviews/2026-11-05-z1-v5-hd-assemble/scripts/check-composition.py
python3 docs/art-reviews/2026-11-05-z1-v5-hd-assemble/scripts/assemble.py
python3 docs/art-reviews/2026-11-05-z1-v5-hd-assemble/scripts/verify.py --acceptance
```

pixel-oracle5กรณีตรวจการประกอบภาพรู้คำตอบ: แนวนอน แนวตั้ง ขนาดผลลัพธ์ ความไม่เปลี่ยนพิกเซลนอกoverlap และการคงcore/พื้นที่นอกfallback ข้อผิดพลาดเชิงไฟล์ทำให้assertล้ม; `--acceptance` คืนexit2หากเกณฑ์รับงานทั้งหมดยังยืนยันไม่ได้ ไม่แปลว่าไฟล์เสีย และไม่ถือว่าQAผ่าน หากต้องตรวจเฉพาะไฟล์ใช้ `verify.py` โดยไม่มีflagนี้
