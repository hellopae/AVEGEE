## วิธีรักษาตำแหน่งและตัวเดิม

ImageGen สร้างรายละเอียดชุดและหมวกจากภาพเดิมกับภาพอนุมัติ ผลสร้างบางภาพมีขนาดต่างจากต้นฉบับ จึงใช้ขั้นตอนส่งออกทางเทคนิค: แยกตัวละครแต่ละท่า จัดขนาดและตำแหน่งกลับกรอบเดิม แล้วนำเฉพาะพิกเซลชุด/หมวกมาประกอบในบริเวณที่กำหนด คงหน้า เขา ผิวแดง หนังสือ และแถบเท้าจากต้นฉบับ เก็บ alpha เดิมทั้งแชนเนล ไม่ได้วาดลายชุดด้วยสคริปต์

`book-walk` รอบเต็ม sheet รายละเอียดนุ่มเมื่อขยาย จึงสร้างใหม่เป็นสี่ส่วน แต่ละส่วน 4×2 ท่า แล้วประกอบกลับ 8×4 ช่องเดิม ใช้ 6 ครั้งแรกและ 4 ครั้งแก้รายละเอียด รวม 10 ครั้ง ไม่มีไฟล์ภาพสร้างดิบหรือไฟล์ชั่วคราวรวมในการส่งมอบ

## หลักฐานและผลตรวจ

- [compare.jpg](compare.jpg): ต้นฉบับซ้าย | ส่งมอบใหม่ขวา ครบทั้ง 6 ไฟล์ แสดงผืนเต็มและทุกท่า อัตราย่อในแต่ละคู่เท่ากัน พื้นตารางใช้แสดงความโปร่งใสเท่านั้น
- [verification.json](verification.json): ขนาด โหมด จำนวนท่า SHA-256 ก่อน/หลัง กรอบตัวและแถบเท้ารายท่า พร้อมค่าความต่าง
- [prompts.md](prompts.md): ชุดคำสั่ง ImageGen และบทบาทของภาพแนบ

ตรวจไฟล์สุดท้ายด้วย Pillow/NumPy เทียบกับสำเนาต้นฉบับ: ชื่อ ขนาด โหมด และจำนวนเฟรมตรงครบ 6 ไฟล์; alpha ตรงทุกพิกเซลทั้ง 5 ไฟล์ RGBA จึงรักษาขอบตัว สเกล และพิกัดเท้าเดิม แถบล่าง 12% ของตัวละครทั้ง 69 ท่าตรงทุกแชนเนล (ต่าง 0 px ทั้งแกน x/y) ส่วน portrait ไม่มีเท้าปรากฏ ตรวจแถบหน้า/ผมและพิกเซลผิวแดงที่ป้องกันไว้แล้วไม่พบความต่าง รวมทั้งไม่มีพิกเซลเปลี่ยนนอกบริเวณชุดที่ใช้ประกอบ

รันคำสั่งทดสอบที่มีอยู่แล้ว โดยไม่แก้ `src/` หรือ `tests/`:

```sh
node --test tests/hero-walking.test.mjs tests/yama-animation-live.test.mjs tests/asset-preload.test.mjs tests/yama-size-a7.test.mjs
```

ผล: 16 tests, 16 ผ่าน, 0 ล้มเหลว ครอบคลุมการอ่านช่อง ทิศทาง การกะพริบตา preload และขนาด/ฐานเท้าจาก alpha ตัวอ่านเกมที่มีอยู่ การทดสอบเรียก Pillow เดิมมี DeprecationWarning ของ `getdata` แต่ไม่มี assertion ล้มเหลว ไม่แก้สคริปต์นอกขอบเขตงาน

3. **หลักฐาน:** มี `compare.jpg` เดิม | ใหม่ ทุกไฟล์ และ README ภาษาไทยในโฟลเดอร์ Y1a นี้ พร้อมข้อมูลตรวจระดับพิกเซล
