## สิ่งที่แก้รอบนี้

รักษาภาพ ImageGen เดิมครบ 3 ระยะ × 8 เฟรม ใช้เฟรมแรกของแต่ละระยะเป็นชั้นนิ่ง
แล้วประกอบภาพวาดต้นฉบับแต่ละเฟรมเฉพาะบริเวณคนงาน ค้อน เชือก ตะขอ และไม้ที่แขวน
ขอบเขต mask อยู่ตำแหน่งเดียวกันตลอดลูป เกลี่ยขอบเชิงพื้นที่ประมาณ 3 px
ท่าเคลื่อนไหวมาจากภาพวาดเดิมทั้ง 24 เฟรม เรียงตามลำดับเดิม

ค่าขอบฐานที่แถว y600/620/635 ลดจาก **9/4/5 px เป็น 0/0/0 px** ตามระยะ
silhouette ในแถบ y595–644 ซ้อนกับเฟรมแรก **1.00000 ทุกเฟรม**
บริเวณนอก motion mask ตรงกันทั้ง RGBA กับเฟรมแรกทุกพิกเซล
บริเวณ mask เต็มค่า 255 ตรงกับ cel ต้นฉบับหลังจัด foot และทำความสะอาด alpha ทุกพิกเซล
ตัวตรวจสีวิญญาณฟ้า–ขาวช่วยตรวจมือ/เท้าที่ชิดขอบ mask ครบทั้ง 24 เฟรม

ต้นทางมีสีแดงอิ่มจัดที่ alpha 1–8 จึงล้าง alpha ≤8 และ RGB ที่โปร่งใสสนิท
ส่งออก WebP แบบ lossless พร้อม `exact=True` เพื่อรักษาค่า RGBA เมื่อถอดรหัสกลับ
ทดสอบเชิงลบด้วยการเปลี่ยนพิกเซลฐานในหน่วยความจำแล้ว ตัวตรวจปฏิเสธด้วย `static scene drift`

รอบนี้เรียก ImageGen เพิ่ม **0 ครั้ง** ใช้ผลงาน ImageGen ในตัวที่สืบทอดมา
ประวัติเดิม 9 คำขอจากเพดาน 12 อยู่ใน `prompts.json`
ไฟล์ต้นทางทั้ง 6 แผ่นตรงกับ worktree ที่ผู้ใช้ระบุแบบ byte-for-byte

## สเปก

ทุกแผ่นเป็น **RGBA WebP แถวเดียว 5632×704 px** จำนวน **8 เฟรม**
แต่ละเฟรม **704×704 px**, **8 fps**, `foot = [352,640]`, `worldWidth = 256`
ความกว้างฐาน **600 px = 218.18 หน่วยโลก** ความละเอียด **2.75 px/หน่วย**
ต้นฉบับทุก cel มีความละเอียดฐานอย่างน้อย 2.7592 px/หน่วย ก่อนย่อลงเพื่อส่งออก

GIF ใช้เวลาเฟรมสลับ 120/130 ms รวม **1,000 ms/รอบ** เพื่อรองรับความละเอียดเวลา 10 ms ของ GIF
เฟรมเกมอ้างอิง fps จาก JSON พิกัดเฟรม `i` คือ `[i*704,0,704,704]`
ช่วงความคืบหน้าของ stage-1/2/3 คือ 0–33%, 33–66%, 66–100%
ตำแหน่งใช้ในเกมตาม brief คือ `img/construction/th/stage-N.webp`
ชุดส่งออกนี้อยู่ในโฟลเดอร์ตรวจภาพตามขอบเขตงาน

## การตรวจภาพ

ตรวจ `frame-strip.jpg` ครบ 24 เฟรมร่วมกับ GIF ทั้งสามไฟล์
ตรวจรอยต่อ 8 → 1 จากเฟรม GIF ที่ถอดกลับใน `gif-review.jpg`
ท่าค้อนมีช่วงยก ลง ตอก และคืนท่า คนงานลากเชือกและแบกวัสดุเปลี่ยนแขน/ขา
ฐานล่างและโครงหลักอยู่กับที่ในภาพเปรียบเทียบ พื้นที่ทำงานยังอ่านเป็นไซต์เปิดสำหรับใช้กับทุกสถานี
ตรวจข้อห้ามเรื่องหลังคา ผนัง และช่อฟ้าจากทั้งสามระยะแล้ว

อัตราความต่างท้ายลูปต่อค่ามัธยฐานภายในลูปอยู่ที่ **1.4514 / 1.1899 / 0.9507** ตามระยะ
ค่าดังกล่าวใช้ประกอบการดูจังหวะกับภาพเฟรมจริง การตรวจลูปครอบคลุมไฟล์ภาพและ GIF

ภาพ `style-compare.jpg` แสดงไม้แดง หินทราย ทอง และแสงอุ่นเทียบกับโรงอาหารบนพื้น HD
ตรวจขอบบนพื้นขาว มืด และน้ำตาลด้วยสายตา ร่วมกับการคัดกรองพิกเซลแดง/เหลืองอิ่มจัด
ที่ขอบ alpha 9–247 ครบทุกเฟรม ได้ **0 พิกเซลทั้งสองสี**

โฟลเดอร์อ้างอิงหลัก `AVEGEE-reference/files/UI New map/New Pic Map Zone1/`
หาไม่พบในเครื่องรอบนี้ จึงรักษา `sources/style-reference.jpg` จากรอบก่อน
ซึ่งมาจากภาพโรงอาหาร `owner-1408/canteen-1409.png` ที่ผู้ใช้ให้ไว้

## ขอบเขตของผลตรวจ

ความนิ่งแบบตรงทุกพิกเซลครอบคลุมบริเวณนอก motion mask และฐานส่วนล่างที่วัด
ภายใน mask ยังมีพื้นผิวรอบตัวคนงานหรือของแขวนติดมาจาก cel เดิมเล็กน้อย
การตรวจสีวิญญาณเป็นตัวช่วยคัดกรองร่วมกับการดูภาพ ส่วน threshold ของ fringe ครอบคลุมสีที่กำหนดในสคริปต์
ขอบเขตการตรวจรอบนี้คือภาพที่ส่งออก metadata และ GIF การวางภาพใน runtime ของเกมเป็นงานเชื่อมต่อปลายทาง

## รันซ้ำ

ใช้ Python 3 พร้อม Pillow และ NumPy สคริปต์ภาพเปรียบเทียบใช้ Arial จากระบบ macOS
เรียกจาก root ของ repo

```sh
python3 -B docs/art-reviews/2026-11-05-construction-anim/export.py
python3 -B docs/art-reviews/2026-11-05-construction-anim/verify.py
```

`verify.py` อ่าน WebP ที่เข้ารหัสจริง เทียบชั้นนิ่งกับ cel แรก เทียบบริเวณเคลื่อนไหวกับต้นฉบับ
ตรวจความไม่ซ้ำของเฟรม การครอบภาพ จุด foot ความละเอียด ขอบ alpha และ GIF ทุกเฟรมกับ atlas
ตรวจขนาดชุดส่งออกไม่เกิน 30,000,000 bytes ผลคำสั่งและ regression เชิงลบอยู่ใน `tests-run.txt`
