## ผังสถานะและคลัง

```text
พ่อค้า / พ่อครัวเติมเสบียงอัตโนมัติเมื่อใกล้หมด
  เบี้ยกรรม -10 × BAL.foodPrice → g.food +10
                 │
                 ├─ ค่าเสบียงงานเดิมของยมทูต/คนงาน
                 ├─ ก่อนมีโรงอาหาร: ให้ข้าวผ่านจัดทีม → -1 ห่อ → ความอิ่ม +40
                 └─ พ่อครัวเดินถึงครัว + ทำงาน 3 วินาที → g.food -1
                       → canteenState[zone].meals +1 (พักผลิตเมื่อมี 6 ชุด)
                           ├─ คนเสิร์ฟเดินถึงโรงอาหาร → meals -1 → worker.meal=true
                           │    → เดินถึงผู้รับ (<40 หน่วย) → ความอิ่ม +40
                           │    → worker.meal=false, served +1
                           └─ ให้ผ่านจัดทีม / เดินไปกินแล้วถึงครัว
                                → meals -1 → ความอิ่ม +40, served +1
```

- เลือกส่งอัตโนมัติเรียงความอิ่มน้อยที่สุดก่อน รวมคนงานและยมทูต ไม่ซ้ำผู้รับที่คนเสิร์ฟอีกคนกำลังไปส่ง; เลือกเฉพาะคนได้จากรายชื่อยมทูตของโซน รวมยักษ์
- คนงานคนเสิร์ฟรับอาหารกินเองที่โรงอาหารได้ เมื่อไม่มีผู้ส่งคนอื่น ไม่ต้องรอคำสั่งผู้เล่น
- ค่าจ้าง/ความเหนื่อย/เสบียงระหว่างทำงานยังใช้ระบบเดิม ไม่มีคนงานผลิตเสบียงฟรี หากเบี้ยไม่พอ ระบบรอ พ่อครัว/คนเสิร์ฟกลับมาทำงานเมื่อเติมเสบียงได้
- ของ `inventory.food` เดิมเก็บไว้ครบสำหรับบริบทไอเท็ม/ต่อสู้ ไม่เอามาหักกับปุ่มจัดทีมอีก จอจัดทีมแสดงชื่อและจำนวนคลังที่ปุ่มใช้ ก่อนสร้างเป็นเสบียงกลาง หลังสร้างเป็นอาหารพร้อมเสิร์ฟ
- การเปลี่ยนหน้าที่/เป้าหมายไม่ทิ้งข้าวที่ถืออยู่ เลิกจ้างคืนข้าวที่ถือให้คลังเดิม แม้คลังจะเกิน 6 ชั่วคราวก็เก็บของไว้ ไม่ตัดทิ้ง

## ย้ายเซฟเก่า

- เพิ่ม marker `foodSystemVersion:1` และรักษา marker โรงอาหารเก่าไว้
- ทุกโซน: เก็บอาหารสำเร็จและจำนวนส่งแล้ว ยกเลิกคิวดำ/เพลิง คืน `remaining × 2` เบี้ยกรรมเฉพาะส่วนที่ยังไม่เสร็จ ไม่คืนส่วนที่ทำแล้ว โหลด snapshot ใหม่ไม่คืนซ้ำ
- ล้างสถานะปรุงของยมทูต ไม่บังคับเปลี่ยนคนงานที่ผู้เล่นมอบหน้าที่ไว้ให้เป็นพ่อครัวเอง
- `mode:'food'` เก่า → `serve`; คงอาหารที่ถืออยู่ เป้าหมายผู้รับ ช่วง pickup/deliver และ progress ของ cook ระหว่างโหลด

- คง migration โรงอาหารแบบ implicit จากเซฟรุ่นเก่าเป็นอาคารจริงโดยไม่สร้างซ้ำ
